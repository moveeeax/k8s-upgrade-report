Amazon EKS control plane and node group order

  1. Upgrade the control plane one minor at a time. EKS refuses to skip minors.
  2. Update the managed addons (vpc-cni, kube-proxy, coredns) to the floor for the new minor *before* rolling nodes.
  3. Roll managed node groups after the control plane. Nodes may lag the control plane by at most 1-2 minors depending on version.
  4. Check every PodDisruptionBudget first - a PDB that can never be satisfied stalls a managed node group update until it times out and rolls back.
  5. Self-managed nodes and Karpenter node pools need their AMI/AMI family pinned version bumped separately.

  • Service mesh version jumps (Istio, Linkerd)
  • Anything outside EKS, AKS and GKE
  • Applying changes to a live cluster - this tool only generates patches
